# Сенсорная перчатка: BNO055 → ESP → монитор порта

Первый этап проекта: прошивка на **C++17 / ESP-IDF** для **Seeed Studio XIAO ESP32-C3** читает ориентацию BNO055 по I²C и выводит её через обычный `ESP_LOGI` в USB-консоль. Исходники находятся в `firmware/`.

## Подключение

| XIAO ESP32-C3 | Модуль BNO055 |
| --- | --- |
| 3V3 | Вход питания 3,3 В согласно маркировке вашего модуля |
| GND | GND |
| D4 / GPIO6 | SDA |
| D5 / GPIO7 | SCL |

Модуль должен быть настроен на I²C согласно его документации. Подтяжки SDA/SCL должны идти к **3,3 В**; проверьте, установлены ли они на модуле. Внутренние подтяжки ESP включены, но не заменяют правильно подобранные внешние. Адрес `0x28` или `0x29` определяется автоматически с проверкой `CHIP_ID=0xA0`. Подключение без внешнего кварца поддерживается; внешний генератор прошивка не включает.

## Сборка и прошивка

Установите ESP-IDF с инструментами для ESP32-C3 по [инструкции Espressif](https://docs.espressif.com/projects/esp-idf/en/stable/esp32c3/get-started/index.html). Проект использует современный I²C master API. Команды из корня проекта:

```bash
source "$HOME/esp/esp-idf/export.sh"
cd firmware
idf.py set-target esp32c3
idf.py build
idf.py -p /dev/ttyACM0 flash monitor
```

Путь SDK и `/dev/ttyACM0` замените на фактические. На Windows укажите, например, `COM3`. Выход из IDF Monitor: **Ctrl+]**. Если прошивка уже записана, монитор открывается командой:

```bash
idf.py -p /dev/ttyACM0 monitor
```

Для изменения подключения или периода:

```bash
idf.py menuconfig
idf.py build
```

Параметры находятся в **BNO055 settings**. По умолчанию: SDA=6, SCL=7, I²C=100000 Гц, период опроса=10 мс, отчёт статистики=5000 мс. Ноль в периоде отчёта отключает статистику. Частота тиков FreeRTOS — 1000 Гц. Допустимый период опроса начинается с 10 мс; частота I²C настраивается до 400 кГц.

`sdkconfig.defaults` задаёт исходные значения, а локальные изменения сохраняются в генерируемом `firmware/sdkconfig`. Этот файл и каталог сборки исключены через `.gitignore`. Команда `set-target` нужна при первой настройке или смене цели; повторно выполнять её перед каждой сборкой не требуется.

## Частота и консоль

В NDOF датчик выдаёт кватернионы с **номинальной частотой 100 Гц**, поэтому целевой период опроса — **10 мс**. Это указано в таблице 3-14 [даташита Bosch BNO055, rev. 1.8](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bno055-ds000.pdf). Частота I²C — скорость передачи битов, она не увеличивает частоту fusion. Чтение не синхронизировано с внутренним генератором BNO055: отдельные результаты могут повторяться даже при исправном датчике; совпадение кватернионов при неподвижности не означает пропуск.

`ESP_LOGI` отправляет текст через **USB Serial/JTAG** и не создаёт I²C-транзакций. Значение 115200 — настройка монитора; на нативном USB оно не задаёт физическую скорость UART. Печать выполняется в том же цикле, что и чтение; отдельных задач и очередей вывода нет. Закрытый или медленный монитор может задержать вывод. Поэтому достижение 100 Гц нужно подтвердить на реальной плате.

## Запуск датчика и ошибки

После паузы на включение BNO055 прошивка сообщает:

```text
Starting BNO055 on Seeed Studio XIAO ESP32-C3 (C++)
I2C initialized: SDA=GPIO6, SCL=GPIO7, frequency=100000 Hz, poll=10 ms
BNO055 confirmed at 0x28, CHIP_ID=0xA0
NDOF ready; polling every 10 ms
```

У сообщений есть стандартный префикс ESP-IDF с уровнем, временем и тегом `bno055`.

| Сообщение | Что проверить |
| --- | --- |
| `BNO055 not found at 0x28 or 0x29` | Питание, общий GND, SDA/SCL, режим I²C и подтяжки модуля |
| `Rejected device at ...` | CHIP_ID подключённого устройства; прошивка также проверит второй адрес |
| `BNO055 write 0x... failed` | Обмен I²C при настройке регистра |
| `NDOF verification failed` | Прочитанные режим, код ошибки BNO055 и результаты I²C; измерения не начинаются |
| `BNO055 read failed` | Ошибка текущего чтения; строка измерения пропущена, опрос продолжается |
| `Waiting for nonzero orientation` | Fusion ещё выдаёт нулевой кватернион; опрос продолжается, сообщение не чаще раза в секунду |
| `SDA and SCL must use different GPIOs` / `I2C bus init failed` | Конфигурация GPIO/контроллера; приложение завершает запуск |

При отсутствии подтверждённого датчика или ошибке его настройки инициализация повторяется с паузой 2 секунды. Это не цикл перезагрузок ESP. После физического отключения и повторного подключения может потребоваться перезапуск ESP и датчика: автоматическое восстановление повреждённого состояния шины не реализовано.

## Формат измерения и калибровка

```text
I (1234) bno055: Quaternion W=1.0000 X=0.0000 Y=0.0000 Z=0.0000 | Cal SYS=0 GYR=3 ACC=0 MAG=0
```

W — скалярная компонента кватерниона, X/Y/Z — векторные компоненты. Порядок и система координат датчика сохраняются: прошивка не преобразует их в экранные оси и не нормализует измерение. Формат совместим с `TBnoLineParser` из `../bno055_viz/include/BnoSample.h`. Визуализация ориентации возможна, но дополнительные функции, использующие ускорение, этим потоком не обеспечиваются.

`Cal` показывает текущие уровни калибровки: SYS — система, GYR — гироскоп, ACC — акселерометр, MAG — магнитометр. **0** означает отсутствие калибровки, **3** — полную калибровку, **1–2** — промежуточные уровни. Неполная калибровка не останавливает вывод ненулевых кватернионов.

Для калибровки гироскопа оставьте датчик неподвижным; для акселерометра последовательно удерживайте его в шести устойчивых положениях; для магнитометра плавно двигайте в разных направлениях, включая движения восьмёркой. Наблюдайте соответствующие уровни и избегайте магнитов и крупных металлических предметов рядом с датчиком. Профиль калибровки в этой версии не сохраняется между включениями.

Каждые 5 секунд дополнительно выводится строка вида:

```text
Timing: poll_hz=100.00 polls=501 samples=501 read_log_avg_us=2000.0 read_log_max_us=3000 overruns=0
```

Это **образец формата, не результат измерения на ESP**. `poll_hz` — частота попыток опроса по их времени начала, `polls` — число попыток за окно, `samples` — число выведенных ненулевых измерений. `read_log_avg_us` / `read_log_max_us` — средняя/максимальная длительность чтения вместе с `ESP_LOGI` в микросекундах. `overruns` считает циклы, вышедшие за границу периода планировщика; сюда могут попасть задержки служебного отчёта и других задач. Счётчики обнуляются после отчёта. Число попыток опроса не показывает число уникальных обновлений внутри BNO055.

Чтобы проверить 100 Гц, наблюдайте несколько отчётов после запуска: частота должна быть около 100 Гц, время чтения с печатью — меньше 10000 мкс, а `overruns` — нулевым. Превышения не скрываются: после медленной операции прошивка делает паузу и не выполняет серию догоняющих чтений. Если вывод мешает, сначала измерьте проблему; без этого заменять `ESP_LOGI` не требуется.

Чтение четырёх flex-сенсоров, беспроводная передача, дополнительные данные IMU и жесты относятся к следующим этапам. Управление мышью по поворотам реализовано в настольных приложениях `desktop/`, описанных ниже.

## Проверки на компьютере

Тесты собирают настоящий `main.cpp` с подменой API I²C, времени и консоли. Они проверяют обнаружение, настройку, обработку ошибок, декодирование и расписание, но не электрическое подключение, реальные задержки или пропускную способность USB:

```bash
# Из корня проекта; ESP-IDF для этих тестов не требуется.
cmake -S firmware/tests -B /tmp/ppproject-host-tests
cmake --build /tmp/ppproject-host-tests
ctest --test-dir /tmp/ppproject-host-tests --output-on-failure
```

Проверка совместимости сформированных строк с существующим визуализатором:

```bash
cmake -S firmware/tests -B /tmp/ppproject-host-tests \
  -DBNO055_VIEWER_INCLUDE_DIR="$PWD/../bno055_viz/include"
cmake --build /tmp/ppproject-host-tests
ctest --test-dir /tmp/ppproject-host-tests --output-on-failure
```

Соседний проект нужен только для этой дополнительной проверки. Прошивка и основные тесты от него не зависят.

Результаты сборки, версия SDK и ограничения выполненных проверок записаны в [firmware/VALIDATION.md](firmware/VALIDATION.md).

## Управление мышью на компьютере

Настольные приложения на C++17 собираются отдельно от ESP-IDF:

```bash
cmake -S desktop -B desktop/build
cmake --build desktop/build -j
ctest --test-dir desktop/build --output-on-failure
```

Зависимости: компилятор C++, CMake, pkg-config, json-c и raylib. Для сборки без графического приложения: `cmake -S desktop -B /tmp/glove-driver-build -DBUILD_GUI=OFF`. Подробности запуска, назначения плоскостей и проверки описаны в [desktop/README.md](desktop/README.md).
