# Glove mouse: драйвер и настройка

Два приложения C++17 для Linux: `glove-mouse-driver` читает ESP и управляет относительным указателем, `glove-mouse-config` предоставляет окно raylib. Сборка независима от ESP-IDF и соседних проектов.

Из корня репозитория:

```bash
cmake -S desktop -B desktop/build
cmake --build desktop/build -j
ctest --test-dir desktop/build --output-on-failure
```

Требуются CMake, pkg-config, C++17, json-c; raylib требуется только при `BUILD_GUI=ON` (по умолчанию). Сборка только драйвера и тестов: `cmake -S desktop -B /tmp/glove-driver-build -DBUILD_GUI=OFF`.

## Профиль

Файл `$XDG_CONFIG_HOME/glove-mouse/config.json`, по умолчанию `~/.config/glove-mouse/config.json`, содержит версию 1, `serial_port`, настройки `x`/`y` с полями `plane`, `invert`, `gain`, а также `deadzone_deg_s`. Defaults: `/dev/ttyACM0`, X=XY, Y=YZ, обе инверсии включены, чувствительность 20 единиц/градус, порог 2°/с.

Допустимы XY/XZ/YZ/None, чувствительность 0.1–200 и порог 0–20°/с. Профиль заменяется атомарно; ошибка записи оставляет старые настройки. Включение мыши и опорная ориентация не сохраняются. Повреждённый профиль отображается как ошибка, исходный файл сохраняется до явного применения настроек.

## Повороты и поток ESP

Перед запуском драйвера закройте IDF Monitor: serial-портом владеет драйвер. Он читает текущий Quaternion/Cal-формат ESP_LOGI напрямую из tty, игнорирует boot/Timing-сообщения и восстанавливает строки из частичных чтений. Можно указать устойчивый путь `/dev/serial/by-id/...`.

| Выбор плоскости | Вращение вокруг опорной оси |
| --- | --- |
| XY | Z |
| XZ | Y |
| YZ | X |
| None | Ось курсора отключена |

Опорные оси задаются положением датчика при центрировании. Для каждой оси курсора выбор независим; одна плоскость может двигать обе оси. Поворот даёт относительное смещение, удерживаемый наклон движения не продолжает. Скачки более 30° между выборками пропускаются. Чувствительность задаётся в единицах относительного ввода на градус; ускорение указателя в окружении Linux влияет на экранные пиксели.

Для реального вывода нужен доступ на запись к `/dev/uinput` и доступ на чтение к выбранному tty. Ошибка доступа отображается в GUI; приложения не меняют права устройств. Не запускайте графическое окно от root. В `--dry-run` uinput не открывается, но вычисления и накопление дробных смещений остаются теми же.

## Запуск и состояния

```bash
# Терминал 1, из корня проекта; сначала проверить без движения настоящего курсора:
./desktop/build/glove-mouse-driver --port /dev/ttyACM0 --dry-run
# Терминал 2:
./desktop/build/glove-mouse-config
```

Для управления настоящей мышью запустите драйвер без `--dry-run`. Он всегда начинает на паузе. После получения данных нужен прогрев 1 секунду, затем управление включается явно в GUI. Пауза сохраняет просмотр данных. Кнопка установки опоры задаёт текущую ориентацию без скачка курсора. Через 250 мс без корректных данных, при отключении порта или сбросе часов ESP мышь выключается; после восстановления требуется явное включение. Драйвер повторяет подключение к порту раз в секунду. Ctrl+C завершает драйвер и освобождает виртуальную мышь.

Опции драйвера: `--port PATH`, `--config PATH`, `--socket PATH`, `--dry-run`, `--help`. `--port` переопределяет загруженный порт для текущего запуска; явное применение GUI сохраняет текущую полную конфигурацию.

## Окно настройки

`glove-mouse-config` запускается независимо от драйвера. Оно показывает состояние соединения, режим `DRY RUN` или `SYSTEM MOUSE` и подтверждённое включение управления. Без драйвера состояние мыши обозначено как неизвестное, кнопки управления недоступны. При потере соединения окно продолжает работать и повторяет подключение раз в секунду; ответы ожидаются не более 500 мс. Закрытие окна (или Ctrl+Q) оставляет драйвер работать с текущими настройками.

- **Axis mapping**: для X и Y независимо выберите XY, XZ, YZ или OFF. XY означает вращение вокруг Z, XZ — вокруг Y, YZ — вокруг X в опорной системе. **Invert** меняет знак, **Units / deg** задаёт чувствительность.
- **Serial port** задаёт tty. **Noise threshold** — порог угловой скорости в °/с. Поля поддерживают Ctrl+A и Backspace.
- **Apply settings** отправляет весь черновик драйверу. Подтверждение появляется после сохранения профиля и применения; ошибка оставляет прежние действующие настройки. Строка `Changes pending` обозначает неприменённые правки. Настройки можно менять без перезапуска драйвера; смена порта выключает управление.
- **Enable motion / Pause motion** включает или приостанавливает движение. **Set reference** принимает текущую ориентацию за опорную без скачка. До свежих данных и прогрева включение недоступно.
- **Live telemetry** показывает последние кватернион W/X/Y/Z, углы yaw/pitch/roll в градусах, уровни калибровки SYS/GYR/ACC/MAG и возраст выборки. Без данных стоят прочерки; старые данные сохраняют видимый возраст и состояние потока.

**Motion preview** показывает условное накопленное относительное движение с масштабом 1:3 и ограничением границами панели. Это не позиция руки и не абсолютная позиция системного курсора. Данные приходят от драйвера примерно 10 раз в секунду; предпросмотр получает накопленные смещения и потому не теряет движение между опросами. Центрирование и новая сессия драйвера сбрасывают его базу. Предпросмотр работает и при `--dry-run`.

## Локальный IPC

Адрес: `$XDG_RUNTIME_DIR/glove-mouse/driver.sock`, fallback `/tmp/glove-mouse-<uid>/driver.sock`. Оба приложения принимают `--socket PATH`. Второй драйвер на том же адресе не вытесняет первый. Закрытие GUI не завершает драйвер.

JSON-запрос и ответ занимают по одной строке. Протокол версии 1, обязательные поля: `version`, неотрицательный целочисленный `id`, `command`. Команды: `get_status`, `get_config`, `set_config` с объектом `config`, `set_enabled` с boolean `enabled`, `recenter`, `shutdown`. Ответ содержит те же version/id, `ok` и `result` либо `error` с code/message. Предел входной строки 64 КиБ и исходящего буфера клиента 256 КиБ; медленный клиент отключается.

`get_status` возвращает подключение serial, waiting/warming/ready/stale, enabled, доступность вывода, dry-run, ошибки, активную конфигурацию, возраст и последнюю выборку (quaternion, angles_deg yaw/pitch/roll ZYX, calibration, device_ms), last_dx/dy, накопленные total_dx/dy, session_id и reference_epoch. Пока выборки нет, `sample` и возраст равны null. Сохранение настроек подтверждается после замены профиля; при ошибке остаются прежние файл и действующие значения. При смене порта управление выключается и начинается переподключение.

## Автоматические проверки

При `BUILD_TESTING=ON` требуется Python 3. CTest запускает C++-проверки настроек, математики, парсера, serial, runtime и событий на подмене устройства, а затем настоящий драйвер в `--dry-run` через PTY и Unix-сокет. Используются временные профили; пользовательский профиль и системный курсор не затрагиваются. Предусмотренные сценарии заранее описаны в `openspec/changes/add-desktop-glove-mouse/specs/tests/glove-mouse/spec.md`.

```bash
ctest --test-dir desktop/build --output-on-failure
# Отдельно интеграционный сценарий:
python3 desktop/tests/integration.py desktop/build/glove-mouse-driver
```

Дополнительная проверка raylib-окна на отдельном виртуальном дисплее (нужны Xvfb, xvfb-run, libX11, libXtst и ImageMagick `import`):

```bash
env -u WAYLAND_DISPLAY xvfb-run -a -s '-screen 0 1280x960x24' \
  env GLOVE_GUI_TEST=1 python3 desktop/tests/gui_smoke.py \
  desktop/build/glove-mouse-driver desktop/build/glove-mouse-config /tmp/glove-gui-validation
```

Сценарий запускает GUI без драйвера, затем PTY-поток с dry-run-драйвером; проверяет управление через окно, применение/ошибки, переподключение и независимое закрытие. Снимки окна сохраняются в указанную папку. Этот сценарий запускается отдельно от CTest и не создаёт системную мышь. Результаты и порядок аппаратной проверки: [VALIDATION.md](VALIDATION.md).
