# Проверка прошивки BNO055

Дата: 2026-11-08. Цель: Seeed Studio XIAO ESP32-C3, `esp32c3`.

## Что изменилось

До реализации в проекте были только документы OpenSpec. В соответствии с последними решениями пользователя план скорректирован:

| До в плане | После в плане и реализации | Зачем |
| --- | --- | --- |
| `main/main.c`, «Использовать C» | `main/main.cpp`, C++17, `extern "C" void app_main()` | Проект на C++ с совместимой точкой входа ESP-IDF |
| «период 20 мс» | `CONFIG_BNO055_OUTPUT_INTERVAL_MS=10` | Целевой опрос 100 Гц вместо 50 Гц |
| Только целевой период | `Timing: poll_hz=... read_log_avg_us=... read_log_max_us=... overruns=...` | Измерение фактической производительности |

Обычный `ESP_LOGI` сохранён в одном цикле. Предложенная ранее замена на `printf` и отдельная задача вывода не реализованы.

Новые файлы прошивки: CMake-проект, `main/main.cpp`, `main/Kconfig.projbuild` и `sdkconfig.defaults`. В `main.cpp` находятся обнаружение и настройка BNO055, чтение/декодирование, вывод и статистика. `.gitignore` исключает производные файлы SDK. Корневой README описывает подключение и команды. `tests/` собирает этот же исходник с подменой API ESP-IDF; внешний визуализатор используется только по явно заданному пути в дополнительной проверке.

## Выполненные проверки

- Активировано существующее окружение `~/esp/esp-idf/export.sh`. Фактический `idf.py --version`: **ESP-IDF v6.1-dev-7651-gc712a0dde38**, кросс-компилятор **riscv32-esp-elf GCC 16.1.0**. Заголовок SDK содержит версию 6.2.0; для воспроизводимости здесь указана именно строка CLI и образа.
- Выполнены `idf.py set-target esp32c3` и сборка пустого C++-приложения, затем сборка готовой прошивки командами из README. Итоговая сборка успешна, предупреждений/ошибок компилятора нет. Выполнен `idf.py size`.
- В `compile_commands.json` проверен последний действующий флаг стандарта: `-std=gnu++17`. У SDK есть собственный `-std=gnu++26`, поэтому стандарт дополнительно задан через `target_compile_options` после флагов SDK.
- Проверены сгенерированные настройки: SDA=6, SCL=7, I²C=100000, опрос=10 мс, FreeRTOS=1000 Гц, USB Serial/JTAG, flash=4 МБ. Отдельная конфигурация SDK в `/tmp` успешно принимает SDA=4 и период=25 мс; исходные настройки проекта при этом не меняются. Проверен тот же путь Kconfig, которым пользуется `menuconfig`, без интерактивного изменения настроек пользователя.
- Host-тесты CMake/CTest проходят с `-Wall -Wextra -Werror`: оба адреса BNO055, отсутствие датчика, чужой CHIP_ID, освобождение ресурсов, последовательность и паузы настройки NDOF, ошибки записей/проверки режима, little-endian и знаковые компоненты, масштаб, поля калибровки, ошибки чтения без публикации старых значений, возобновление вывода, нулевой кватернион, низкая калибровка, ограничение частоты диагностики, расчёт статистики и пауза после превышения периода.
- Вызван настоящий `app_main()` с подменённым временем/I²C: проверены стартовая пауза, регулярный опрос с интервалом 10 мс после привязки к тику и отсутствие измерений при отсутствии BNO055. Это модель планирования, а не измерение скорости процессора или шины.
- Дополнительная проверка использует неизменённый `TBnoLineParser` из `../bno055_viz/include/BnoSample.h`: строки, сформированные `ReadAndLog()`, успешно разобраны с ESP_LOG-префиксом и без него. Проверены отрицательные компоненты, уровни калибровки и временная метка; стартовые и служебные строки не распознаются как измерения.
- `openspec validate add-bno055-console-firmware --strict --json`: проверка пройдена без замечаний.

## Аппаратная проверка не выполнена

Последовательных устройств `/dev/ttyACM*` и `/dev/ttyUSB*` нет. Прошивка на ESP не записывалась, монитор физической платы не запускался. Не проверены электрическое подключение, реальная ориентация/калибровка BNO055, фактические 100 Гц и задержки `ESP_LOGI` на ESP.

После подключения платы нужно выполнить команды `flash monitor` из README, повернуть датчик и посмотреть несколько строк `Timing:`. Затем проверить запуск без BNO055. Численные примеры в README — образцы формата, не результаты аппаратного тестирования.
